# Resume optimise

> **Recruiter reality:** First screen is **6–10 seconds**. They match your **title, company, and top 3 bullets** to the open req — not your design skills.

## Do this today

- [ ] Run your resume through the [CV Analyzer](/jobs) — fix the **top 3** issues only
- [ ] Make your **most recent job title** match what you're applying for (e.g. "Software Engineer" not "Associate" if that's the market title)
- [ ] Add **one metric** to your strongest bullet — recruiters search for numbers
- [ ] Stop after **2 revision rounds** — then apply

## What recruiters scan first (in order)

1. Current role + company name (brand recognition helps)
2. Total years of experience vs req (3–5 vs 5–8)
3. Location / remote / notice period (put near contact if India market)
4. Skills that match their boolean search (React, Node, Java — mirror the JD)
5. GitHub only if active — dead profile is worse than omitting

They **skip:** paragraphs of summary, skill bars, "hobbies," and 30 technologies listed.

## One-page structure checklist

| Section | Must have |
|---------|-----------|
| Contact | Email, phone, LinkedIn, city — GitHub **only if repos are current** |
| Summary | **Optional.** 2 lines max, or skip and use space for bullets |
| Experience | 2–4 bullets per role, **newest first**, strongest metric in bullet 1 |
| Projects | 1–2 entries if 2+ YOE; 2–3 if fresher — see [Project work](/tips?tab=projects) |
| Skills | **8–12 terms** grouped: Languages, Frameworks, Tools — match target JD |
| Education | One line if 2+ YOE |

## ATS rules (what actually gets you past filters)

- Standard headings: Experience, Projects, Skills, Education
- **Action verb + metric + outcome** per bullet (XYZ formula)
- Paste keywords from the **job description** — 3–5 real skills you actually used, not keyword stuffing
- No tables, columns, or graphics that break parsing
- PDF from Google Docs, Word, or LaTeX — not Canva image exports
- **1 page** for &lt;6 YOE; 2 pages only if every line earns its place

## XYZ formula (copy this pattern)

**Weak:** "Worked on backend APIs using Node.js."

**Strong:** "Built REST APIs in Node.js serving **50k daily users**, cutting p95 latency **from 800ms to 200ms**."

Template: **Accomplished [X] as measured by [Y], by doing [Z].**

Recruiters forward resumes where bullets prove **scope** (users, revenue, latency, team size, release cadence).

## Action verbs that survive screening

`Built` · `Shipped` · `Reduced` · `Improved` · `Led` · `Designed` · `Automated` · `Scaled` · `Migrated` · `Optimized`

Avoid alone: *helped, worked on, responsible for, passionate, dynamic*

## Common mistakes (recruiter pet peeves)

| Mistake | Fix |
|---------|-----|
| Same resume for every role | Tailor **skills + top 2 bullets** per application (15 min) |
| Projects longer than experience | Trim projects; experience wins at 3+ YOE |
| No notice period / location | Add one line — saves back-and-forth |
| Lying about metrics | Use ranges or "team of 5" if exact number is NDA |
| 4th rewrite of one bullet | Ship and apply |

## When to stop overthinking

| Signal | Action |
|--------|--------|
| Same bullet rewritten 3+ times | Ship it |
| ATS score improved on second scan | Apply this week |
| Missing keywords for target role | Add 3 from JD, not 30 |
| No applications in 7 days | Resume is good enough — apply |

## Ship-it rule

**Maximum 2 ATS scans per week.** Recruiters hire candidates in pipeline, not perfect PDFs. After pass two, spend time on applications and outreach.
